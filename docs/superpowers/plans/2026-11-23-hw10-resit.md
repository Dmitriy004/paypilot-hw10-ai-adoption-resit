# HW10 Resit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for technical work. Author-only stages are human work and must never be delegated to an assistant or subagent. Execute one approved stage at a time.

**Goal:** Prepare and run the new-repository experiment in the exact mentor-requested sequence, with genuine author participation and immutable comparators.

**Architecture:** Fresh course checkout and separate venv; the baseline stays at its canonical path from the start. Every experimental stage gets its own chronological commit; old homework remains historical and read-only.

**Tech Stack:** Windows PowerShell, Python 3.12, pinned pytest/pytest-cov from the course kit, Git; later Claude Code CLI.

**Spec:** docs/superpowers/specs/2026-11-23-hw10-resit-design.md

## Global Constraints

No reuse of old custom tests/reports/timers/history. No assistant-written baseline or generated output before the author's own baseline freeze. Real start/end/pause events only. No changing manual/generated after generation, except the course's preserved original-red removal procedure. No paid call without current authorization. Prior exposure remains disclosed, not magically erased.

## Review Focus

- The new repo must have no old homework commits or implemented baseline/generated suites.
- A not-started timer must never appear as zero completed writing time.
- Canonical path commits, not just temporary source files, must prove the sequence.
- The first generated response must be preserved before running it; no output replacement for better results.
- Frozen hashes and per-function review records must survive all later reporting/publication steps.
